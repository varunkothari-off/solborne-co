# Harness reproduction
Use a parent working directory with the exact source copied to validation/ and the proposed lock applied. Run npm ci --ignore-scripts in validation; run the authored tests, Astro check, tsc, build. Place harness/ alongside validation/. In harness, run npm ci --ignore-scripts, then node parse-controller.mjs, node render.mjs, node controller.mjs, node delivery.mjs, node research-consent.mjs. Research consent harness uses a test-only bundled gate module and synthetic fetch promises; production source gates remain false and no provider is contacted. The first command parses/bundles the actual extracted Astro controller; authored text assertions and plain tsc alone do not establish Astro script validity. render.mjs uses Astro App.render with ASTRO_NODE_AUTOSTART=disabled, not a socket or browser. It creates the local rendered fixtures consumed by the DOM harnesses. Every external fetch is forbidden in the harness checks. The controller API mock is isolated to the test and must not be copied into production. JSDOM is only a harness dependency, not an app dependency.

Discovery increment: run the additional src/lib/publicDiscovery.test.ts with the existing authored test suite, then run node discovery.mjs after production build and render.mjs. Discovery reads built marketing HTML, robots and sitemap plus the rendered Walk fixture. It does not certify public HTTPS/DNS/lead capture. No new test or production dependency.

Linked catalog correction: run src/lib/catalogCopy.test.ts alongside the existing source suite and node catalog.mjs after build. It checks every generated category/item route and linked target, including website-builder scope and the blocked contact channel. No network/provider proof is implied.
